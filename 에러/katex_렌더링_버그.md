## 버그 1: `\sqrt{...}` 안의 숫자가 전부 사라짐 ★ 가장 오래 잡은 것

### 증상
- 문제 안에 `$\sqrt{5}$`, `$\sqrt{\dfrac{32}{5}}$` 등을 써도 **√ 기호만 보이고 안의 숫자/식이 안 보임**
- 파일 인코딩/KaTeX 문법은 멀쩡, 1회차 파일은 같은 패턴으로 잘 나옴

### 원인
CSS에 **전역** 규칙으로
```css
svg { background: white; }
```
를 넣어 둠. 내 커스텀 도형(정사각형·정육각형 등)에 흰 배경 주려고 쓴 건데, KaTeX가 `\sqrt` 기호를 SVG로 그리기 때문에 **KaTeX 내부 SVG까지 이 규칙에 덮여** radicand(루트 안 숫자)가 가려지거나 레이아웃이 무너짐.

### 해결
스코프를 좁힌다:
```css
.fig svg { background: white; }
```
내 도형은 `.fig` div 안에 있고 KaTeX SVG는 아니므로 충돌 사라짐.

### 교훈
- **KaTeX와 같이 쓸 때 `svg { ... }` 같은 element-level 전역 셀렉터 금지.**
- 커스텀 도형용 스타일은 반드시 클래스 스코프 (`.fig svg`, `.my-diagram svg` 등) 로 제한할 것.

## 버그 2: `0<a<1` 쓰면 HTML 파서가 `<a`를 앵커 태그로 오인

### 증상
- `$0<a<1$` 라고 쓴 문제 (Q10)가 아예 통째로 사라짐
- 브라우저 HTML 파서가 `<a<1$...` 이후를 anchor 태그 열림으로 해석해서 KaTeX가 받기 전에 삼켜버림

### 해결
두 가지 중 하나:
1. **양옆에 공백**: `$0 < a < 1$` (1회차 파일이 쓰는 방식, 제일 안전)
2. KaTeX 매크로: `$0\lt a\lt 1$` — 작동은 하지만 굳이 바꿀 필요 없음

### 교훈
- HTML 안에 수식 `$...$`을 써도 **브라우저는 먼저 HTML로 파싱한 뒤** KaTeX에 넘긴다. `<문자` (공백 없음)은 태그 시작으로 보임.
- `<`, `>` 연산자는 반드시 **공백 포함**해서 쓴다.

## 버그 3: `$$...$$` display math가 인접한 `$...$`과 파싱 충돌

### 증상
- 인라인 `$0 < x < 1$ 일 때,` 바로 아래에 `$$\sqrt{...}+\sqrt{...}+\sqrt{...}$$` 를 썼더니
- display math 안 루트가 전부 빈 √ 로 나옴 (delimiter 경계가 꼬임)

### 해결
- 아예 display math를 쓰지 말고 인라인으로:
  ```
  $\sqrt{\dfrac{1}{x^2}} + \sqrt{\left(x+\dfrac{1}{x}\right)^2 - 4}$
  ```
- `\dfrac`, `\left(...\right)^2` 만 써도 식은 충분히 크게 나옴
- 정말 display 필요하면 `$\displaystyle ...$` 써도 됨

### 교훈
- auto-render의 `$$...$$` 는 인접한 `$...$` 사이 공백이 모호하면 경계를 잘못 잡음.
- **인라인 `$...$` + `\dfrac` + `\left\right` 조합**이 가장 안정적. 1회차 파일이 이 방식으로 전부 작성됨.

## 공통 디버깅 절차

1. KaTeX 수식이 이상하게 나올 때 **1회차 파일 (mock_exam_1.html)과 비교**한다. 동일 문법인데 2회차에만 깨지면 → **CSS 충돌 / 전역 셀렉터** 의심.
2. 커스텀 CSS 중에 element-level 셀렉터 (`svg`, `div`, `span` 등) 있는지 확인하고 반드시 클래스 스코프로 전환.
3. `<`, `>` 는 수식 안에서도 **양옆 공백**.
4. display math `$$...$$` 보다 **인라인 `$...$`** 기본값.
